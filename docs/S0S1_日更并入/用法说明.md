# S0S1 主表日更并入 · 用法说明（例程复现）

供例程「S0S1主表日更并入」（约每天 07:00 Asia/Shanghai，flexible±15）调用。  
**红线**：不碰线上推理服务、不写服务器库、不真收、不上线；AF `incremental` 只读。

## 1. 入口

```bash
source ${VENV_DIR}/bin/activate
python -u ${PROJECT_ROOT}/S0S1_日更并入/脚本/日更并入_S0S1.py
```

可选参数：

| 参数 | 含义 |
|---|---|
| （无） | 目标日 = **Asia/Shanghai 昨天** |
| `--day YYYY-MM-DD` | 覆盖目标观察日 |
| `--force` | 忽略「已是最新」幂等跳过，仍要求该日完整（末批小时≥19） |

## 2. 退出码（例程怎么判）

| 码 | 含义 | 例程建议 |
|---|---|---|
| **0** | 成功并入，或 **幂等跳过**（S0/S1 已覆盖目标日） | 正常 |
| **10** | **日未走完**：该观察日在 incremental 中末批小时位 `<19`（或尚无批） | **可预期跳过**，勿当事故吵经理（除非连续多天） |
| **1** | 真实失败（构建/校验异常） | 告警；看 `日志/` |

## 3. 完整日判定（与 S0 口径一致）

只读目录：`${AF_INCREMENTAL_DIR}/batch=YYYYMMDDHHMM/`  
仅计带 `_SUCCESS` 的批；该日 `max(batch)` 的小时位 `substr(batch,9,2) >= 19` → 完整日。

## 4. 幂等

若 `S0 主表` 与 `S1 特征矩阵` 的 `max(观察日)` **均 ≥ 目标日** → 打印「已是最新，无操作」，**exit 0**，不重写主文件（md5 不变）。

## 5. 落后时做什么

1. **S0**：把 `S0_底表/脚本/构建_全航司日价底表_S0.py` 的 `OBS_TO` 设为目标日；输出到临时目录；校验（无通程、无重复键、主表无回补、**旧日行数 diff=0**）后原子替换主表/对照/回补；替换前小备份 `S0_底表/数据/_备份_日更前_<day>/`（只留最近 3 份）。
2. **S1**：备份矩阵 → 清 `_DONE_01`…`_DONE_06`（保留 `_DONE_00_清单`）→ 全量跑 `S1_特征/脚本/构建特征_S1.py`（约 2 分钟）→ 校验行数=S0、旧日 diff=0。
3. 写：
   - `S0S1_日更并入/增量说明_最新.md`
   - `S0S1_日更并入/状态/上次成功.json`
   - `S0S1_日更并入/日志/日更_*.log` 以及 S0/S1 子构建日志

口径摘要：末批 / 70% 规则、剔通程（`len(flight_no)==7`）、剔回补、主表 dtd 0..30。

## 6. 例程可粘贴文案（一两段）

每天约 07:00（上海）跑「昨天」：激活 `.venv` 后执行  
`python -u …/S0S1_日更并入/脚本/日更并入_S0S1.py`。  
exit 0=已并入或已是最新；exit 10=昨天价批尚未走完（末批小时&lt;19），属可预期跳过；其它非 0 查 `S0S1_日更并入/日志/`。不碰线上推理服务、不写服务器库。

## 7. 失败谁收

- 可预期跳过（码 10）：例程静默即可；连续多天仍 10 再找值班。
- 真实失败（码 1）：把最新 `日志/日更失败_*.log` 或 `日更_*.log` 尾部交给经理/值班 Agent；**不要**手工改 （线上推理服务） 或服务器库「抢救」。
